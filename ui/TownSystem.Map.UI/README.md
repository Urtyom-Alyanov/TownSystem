# Модуль карты TownSystem

## Запуск карты

Из корня решения на Windows с SDK .NET 10:

```powershell
dotnet run --project ui/TownSystem.Map.UI/TownSystem.Map.UI.csproj
```

В Visual Studio выберите `TownSystem.Map.UI` запускаемым проектом. `TownSystem.UIApp` — окно общего приложения. Карту в него подключает команда по примеру ниже.

Демонстрационная карта содержит 1600 × 800 клеток и по умолчанию заполняет область просмотра. Щелчок левой кнопкой выбирает участок, колесо меняет масштаб у указателя, а кнопки «+» и «−» приближают и отдаляют карту от центра. Увеличенную карту можно перемещать, удерживая левую или правую кнопку. «Вся карта» показывает все клетки, «По экрану» заполняет область просмотра, «Новая карта» создаёт другую местность того же размера.

Генератор задаёт случайные высоты на нескольких сетках разной плотности и плавно смешивает соседние значения. Крупная сетка формирует заливы и горные массивы, более плотные уточняют берег и склоны. На больших картах генератор проводит извилистое русло и притоки до береговой линии. В модели река является водоёмом с признаком IsRiver и названием «Река». На слое «Местность» равнины бежевые, леса зелёные, горы серые, реки и водоёмы голубые. Слой «Рельеф» показывает высоты пятью цветами с границами через 100 м. Для воды есть отдельные цвета глубины до 50 м и от 50 м. Тонкие контуры разделяют ступени на суше. Точный тип участка и его высота доступны при выборе клетки.

На слое «Ресурсы» видны районы с разной плотностью месторождений и отдельные находки. Железо, медь и уголь распределяются по горным участкам, нефть и газ по низким равнинам, древесина по лесам. Вероятность находки плавно меняется между соседними участками. В богатых районах запасы в среднем выше.

## Как работать с моделью

- `new MapGenerator().Generate(width, height)` создаёт карту. Для воспроизводимого примера можно передать число в `new MapGenerator(42)`.
- Координаты начинаются с нуля. `X` растёт вправо, `Y` — вниз. Перед обращением проверьте `map.IsInside(x, y)`, затем используйте `map[x, y]` или `map.GetCell(x, y)`.
- `cell.Occupy()` возвращает `true`, если участок удалось занять. После удаления объекта вызовите `cell.Release()`. `cell.CanBuild` учитывает тип местности и занятость, а `cell.Terrain.IsPassable` описывает проходимость местности.
- `cell.Deposit` может быть `null`. `Extract(amount)` возвращает количество, которое фактически удалось добыть. Запас хранится в `Amount`.

## Как проверять размещение

Перед размещением используйте `cell.CanPlace(kind)`. Когда объект действительно появляется, вызовите `cell.Occupy(kind)`. После удаления объекта освободите занятые им клетки через `cell.Release()`.

| Режим | Подходящий участок |
| --- | --- |
| `Building` | Свободная клетка, где доступна обычная застройка |
| `LandInfrastructure` | Свободная клетка суши, включая лес и горы |
| `WaterInfrastructure` | Свободная клетка воды, включая реку |
| `Extraction` | Свободная клетка суши с ненулевым запасом нужного ресурса |

Для обычной постройки можно по-прежнему использовать `cell.CanBuild` и `cell.Occupy()` без аргументов.

```csharp
bool minePlaced = cityMap[mineX, mineY].Occupy(PlacementKind.Extraction, NaturalResource.Iron);
bool supportPlaced = cityMap[waterX, waterY].Occupy(PlacementKind.WaterInfrastructure);
bool buildingPlaced = cityMap.TryOccupyArea(x, y, 2, 3, PlacementKind.Building);
```

`CanPlaceArea` проверяет прямоугольный участок для предварительного показа. `TryOccupyArea` проверяет весь участок и только после этого занимает клетки. Он применяет один режим ко всему прямоугольнику. Для смешанного объекта, например моста с опорами на берегах и в воде, модуль моста проверяет каждую часть по её режиму.

Ограничения конкретного объекта задаёт его модуль. Например, порт проверяет выход к воде, судно может проверить `cell.Relief.Height` и `WaterBody.IsRiver`, а дорожный модуль учитывает уклон. `Terrain.IsPassable` описывает исходную местность. Движение по построенному мосту или дороге определяет транспортный модуль.

Модуль объекта хранит его координаты и список занятых клеток. Изменения общего состояния карты выполняйте последовательно в потоке симуляции.

## Как встроить карту в WPF

Добавьте ссылку на `TownSystem.Map.UI.csproj` в проект окна. Из `ui/TownSystem.UIApp` она выглядит так:

```xml
<ProjectReference Include="..\TownSystem.Map.UI\TownSystem.Map.UI.csproj" />
```

В XAML окна объявите пространство имён

```xml
xmlns:maps="clr-namespace:TownSystem.Map.UI.Views;assembly=TownSystem.Map.UI"
```

и поместите в разметку

```xml
<maps:MapView x:Name="CityMap"/>
```

После `InitializeComponent()` передайте существующую карту. `CanGenerateMap = false` оставляет генерацию у общего приложения и скрывает кнопку «Новая карта».

```csharp
var mapViewModel = new MapViewModel(cityMap) { CanGenerateMap = false };
CityMap.DataContext = mapViewModel;
```

`MapViewModel` находится в `TownSystem.Map.UI.ViewModels`. Модель `cityMap` должна быть той же, которую используют модули зданий и добычи. После изменения вызовите `mapViewModel.RefreshCell(x, y)` в потоке интерфейса. Это обновит характеристики и обозначение участка, сохранив выбор. Выбранная модель клетки доступна через `mapViewModel.SelectedCell?.Cell`.

### Где показывать городские объекты

`CityMap.ObjectLayer` — слой поверх местности и месторождений. Он смещается и масштабируется вместе с картой. В каждой клетке по `MapView.CellSize` единиц в ширину и высоту. Чтобы поместить подготовленный элемент в клетку, задайте его положение и добавьте его в слой.

```csharp
Canvas.SetLeft(cityObject, x * MapView.CellSize);
Canvas.SetTop(cityObject, y * MapView.CellSize);
CityMap.ObjectLayer.Children.Add(cityObject);
```

В этом примере `cityObject` — элемент WPF, созданный другим модулем. Карта обрабатывает клики по координатам даже под нанесёнными объектами. Слой очищается при смене карты. Участники, отвечающие за застройку, транспорт и другие варианты, хранят модели своих объектов в собственных модулях.
